# 注册验证码方案思路

背景：新增注册功能后，需要补充基础防护，降低批量注册、撞库的风险。在尚未接入第三方服务的情况下，可以先预埋接口与前端展示结构，后续按环境启用。

## 方案建议

1. **采用成熟验证码服务**  
   推荐使用 hCaptcha / reCAPTCHA v2/v3 / 腾讯防水墙等 SaaS 服务。它们提供 React/Next.js 组件，可快速集成，且具备风险识别能力。  
   - 前端：在注册表单提交前请求验证码，并将 `token` 附带到注册接口中。  
   - 后端：在 `/api/v1/identity/register` 中校验 `token`，失败时返回 422。  
   - 配置：密钥写入 `.env`（如 `CAPTCHA_SITE_KEY`、`CAPTCHA_SECRET`），通过 `process.env` 读取。

2. **后端限流与审计**  
   - 对注册接口增加基础限流，可使用 Edge Middleware 或带 Redis 的限流器实现。  
   - 将验证码失败、注册失败次数写入 `AuditLog`，便于后续监控。

3. **灰度与回退策略**  
   - 在前端保留「验证码配置缺失时隐藏组件」的逻辑，避免阻塞本地开发。  
   - 后端若检测到密钥缺失，可直接跳过校验并写日志，以便环境验证时快速发现。

4. **后续增强**  
   - 引入短信或邮件验证，确保邮箱/手机号真实有效。  
   - 将注册接口加入统一安全测试流程，覆盖暴力破解、参数绕过等场景。

## 开发步骤（建议）

1. 为注册 API 增加 `captchaToken` 字段与校验逻辑，接入服务端验证 SDK 或 REST API。  
2. 注册页根据环境变量渲染验证码组件，并在提交时携带 `captchaToken`。  
3. 更新 `README`/部署文档，声明新增配置项及校验流程。  
4. 补充集成测试，模拟验证码成功/失败与限流场景。

以上步骤可在后续迭代中逐步实现，当前版本先用文档记录，避免阻塞注册功能上线。
