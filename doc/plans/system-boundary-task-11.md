# 系统边界改造任务 11：OpenAPI 契约与测试覆盖补强

## 背景

系统边界计划阶段 0 要求生成“按子系统分组”的 OpenAPI 草案，并在基线中记录关键测试。当前仍缺少统一的 API 契约和与之相对应的自动化校验，导致前后端协作与接口演进缺乏权威来源。

## 目标

- 为 Accounts & Ledger、Income & Tax、FX、Reporting、Identity 等子系统整理 OpenAPI 契约，并生成 `doc/openapi.yaml`（或等价文档）作为唯一事实来源。
- 将关键接口纳入契约测试：后端利用 `pnpm vitest`/集成测试校验响应结构，前端利用类型生成或契约校验工具保证调用一致。
- 在 `doc/system-boundary-plan.md` 的基线章节同步更新“测试覆盖”说明，确保契约和测试有闭环。

## 执行步骤

1. 梳理现有 API 路径，按照子系统分组，定义请求/响应结构与鉴权需求，生成 `doc/openapi.yaml`（支持后续自动化工具）。
2. 集成契约检查：可选地在 `pnpm test` 中增加 schema 校验（例如使用 `zod`/`supertest` + OpenAPI 校验器）。
3. 前端更新 API 客户端，使用契约生成的类型（或校验逻辑）辅助调用，确保路由重构后调用不出错。
4. 文档记录契约维护流程、验证命令以及变更指南。

## 验收标准

- `doc/openapi.yaml` 或等效契约文件存在，并包含所有核心接口。
- 契约校验集成到 CI 或本地测试流程；出现接口变更时能自动提示不一致。
- 基线文档描述了契约、测试与生成/验证命令，方便团队遵循。
