# 系统边界改造任务 10：Settings 与 Identity 子系统收敛

## 背景

系统规划中强调“普通用户聚焦个人账户与收入、管理员可模拟登录维护全局规则”，同时要求 `/settings` 页面集中管理基准币种、展示币种、统计日期、城市、税务规则等。当前接口仍分散在 `/city-changes`、`/settings`、`/rules/*` 等路径，权限与审计也未统一。

## 目标

- 形成独立的 Settings/Identity 子系统，明确用户自助设置 vs 管理员操作的接口边界。
- 收敛相关 API（如 `/city-changes`、`/user/profile`、`/settings`）至统一命名空间，并补充权限、审计与幂等逻辑。
- 更新前端调用与状态管理，确保设置变更后触发相关 SWR 缓存失效。

## 执行步骤

1. 梳理现有设置类接口与字段，确定 Settings/Identity 数据模型与 API 契约（普通用户、管理员、审计要求）。
2. 在 `src/app/api/v1` 下新建命名空间（如 `/identity`），迁移城市迁移、用户资料、设置更新等路由，并统一使用 `audit.log`、`Idempotency-Key`。
3. 重构前端 `/settings` 页面、用户资料面板与相关 hooks，确保使用新的 API；更新权限校验逻辑（普通用户 vs 管理员），并同步调整 UI 中的跳转与提示。
4. 编写/更新测试覆盖（API 与前端的集成用例），确保设置变更后能驱动收入回算、报表刷新等逻辑。

## 验收标准

- 所有 Settings/Identity 操作的 API 路由位于统一命名空间，权限/审计一体化。
- 前端 `/settings` 页面与关联模块使用新接口，SWR/状态在变更后正确刷新。
- 文档提供访问控制与审计说明，测试通过。
