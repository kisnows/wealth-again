# 账户模块合规改造方案（2025-02-15）

## 背景
- 依据《doc/account-all.md》《doc/prd.md》及《doc/frontend-spec.md》，当前账户模块仍存在与规范不符的实现差异。
- 主要问题集中在账户类型支持、归档账户行为、账户详情页交互以及交易记录字段完备性等方面。

## 问题与改造任务

1. **账户类型缺失 OTHER**
   - `src/lib/api/accounts.ts` 与前端表单未暴露 `OTHER` 选项，无法创建“其他”类型账户。
   - `POST /api/v1/accounts` 未校验 `accountType`，存在脏数据风险。
   - **任务**：补齐枚举、前端表单选项与后端校验。

2. **归档账户仍可执行交易 / 估值**
   - PRD 要求归档账户禁止新增交易或估值；当前存款、取款、转账、估值接口缺乏状态校验。
   - **任务**：在 `/entries/*` 与 `/valuations` 写操作中校验账户状态；前端对话框过滤归档账户；补充回归测试。

3. **账户详情页不符合交互规范**
   - 缺少账户元数据区块、交易表格筛选/分页/导出、估值与本金双曲线等。
   - **任务**：重构 `src/app/accounts/[id]/page.tsx`，新增模块化组件（交易表格、汇总卡片、图表），补充 `data-testid`。

4. **交易记录缺少附件字段**
   - 规格要求 `TxnLine` 保存 `attachmentUrl`；目前 Prisma 模型及 API 响应均未覆盖。
   - **任务**：为 `TxnLine` 增加可选 `attachmentUrl` 字段（含迁移），更新接口序列化与前端展示。

5. **AccountTable 组件超出 500 行限制**
   - 违反前端规范，影响可维护性。
   - **任务**：拆分为子组件（账户卡片、过滤器、交易列表等），控制单文件行数。

## 预期交付
- Prisma 迁移与数据库生成通过，相关 API 测试覆盖归档校验与新字段。
- `/accounts` 与 `/accounts/[id]` 页面符合交互规范，并提供稳定的汇率与交易视图。
- 现有 lint/test 全部通过，新增功能具备基础测试验证。
- 文档无需额外调整（规范已覆盖）。
